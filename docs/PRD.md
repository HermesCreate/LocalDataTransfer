# Data Transfer 工具产品需求文档

## 文档目的

本文档描述一个运行在本机的本地网页传输工具。其他 Agent 只需要按本文档实现，就可以复现当前版本的功能、交互流程和视觉设计。

工具用于在本地文件系统与 SSH 服务器之间传输文件或目录。用户可以手动输入本地路径，也可以点击文件夹图标调用系统文件夹选择器。服务器列表来自本机 `~/.ssh/config`，支持多选。底层使用 `rsync + SSH`，显示总体进度、速度、剩余时间和日志，并支持中断后续传。

## 1. 产品定位

### 1.1 目标用户

需要在 macOS 本地环境与一台或多台 SSH 服务器之间传输视频、数据集和大型目录的开发者、算法工程师和数据处理人员。

### 1.2 核心价值

- 用图形界面替代手动拼接长的 `rsync` 命令。
- 复用用户已有的 SSH 别名、用户、端口和密钥配置。
- 支持多个服务器批量传输，避免重复操作。
- 传输过程中能够看到速度、进度和当前目标。
- 中断后可以再次启动并继续未完成的传输。

## 2. 产品范围

### 2.1 必须支持

- 本地路径手动输入。
- 本地文件夹图标选择器。
- 文件夹选择结果立即持久化，下次打开默认恢复。
- 从 `~/.ssh/config` 读取具体 `Host` 别名。
- 多选服务器。
- 本地到服务器、服务器到本地两种方向。
- 远程路径输入。
- 使用 `rsync + SSH` 传输。
- 实时显示百分比、速度、预计剩余时间和日志。
- 停止当前传输。
- 使用 `--partial` 支持再次启动时续传。
- 本地后台服务和浏览器界面分离运行。

### 2.2 不在范围内

- 保存 SSH 密码。
- 修改或写入用户的 `~/.ssh/config`。
- 服务器端文件浏览器。
- 远程路径的自动补全。
- 断点续传任务队列。
- 多个独立传输任务并行调度。

## 3. 用户场景

### 场景 A 上传到一台服务器

1. 用户填写本地目录。
2. 用户从服务器下拉列表选择 `11.20`。
3. 用户填写远程路径，例如 `/data/shared/datasets/real_world_video_data/edit_cut/20261116/mono-2`。
4. 用户选择“本地 → 服务器”。
5. 用户点击“开始传输”。
6. 工具后台拼接 `11.20:/data/.../mono-2`，执行一次 `rsync`。

### 场景 B 上传到多台服务器

1. 用户从服务器下拉列表多选 `11.20`、`H800-1`、`H800-2`。
2. 用户填写一个远程路径。
3. 工具为每个别名拼接最终地址。
4. 工具按选择顺序逐台传输同一份本地数据。
5. 日志按服务器显示开始、进度、完成或失败。

### 场景 C 从多台服务器下载

1. 用户多选服务器并选择“服务器 → 本地”。
2. 工具从每台服务器读取同一个远程路径。
3. 如果选择了多台服务器，下载目标自动分为：

   ```text
   本地目标目录/11.20/
   本地目标目录/H800-1/
   本地目标目录/H800-2/
   ```

   这样可以避免不同服务器之间互相覆盖文件。

## 4. 页面结构与视觉设计

### 4.1 页面整体

- 页面类型是本机浏览器中的单页工具界面。
- 页面最大宽度约为 `1180px`，水平居中。
- 页面背景色为 `#F3F6F9`。
- 页面顶部留白约 `42px 32px`。
- 所有内容使用白色卡片承载。
- 卡片圆角约 `18px`。
- 卡片边框使用浅灰蓝色，阴影轻量且柔和。
- 使用系统无衬线字体。macOS 优先使用系统字体，浏览器回退到 `Inter`、`Segoe UI` 或 `sans-serif`。

### 4.2 页面顶部

顶部左侧包含：

- 小型英文眉题：`LOCAL TOOL / RSYNC + SSH`
- 主标题：`Data Transfer`
- 副标题：`用一个清晰的界面，在本地和 SSH 服务器之间传输文件与目录。`

顶部右侧包含“本机运行”状态胶囊，带绿色状态点。

### 4.3 主区域布局

主区域为两列布局：

- 左列约占 `1.08fr`，宽度略大，放置传输设置。
- 右列约占 `0.92fr`，放置实时状态。
- 两列间距约 `16px`。
- 屏幕宽度小于约 `820px` 时改为单列。

### 4.4 传输设置卡片

卡片标题区域包含：

- 英文眉题：`TRANSFER SETUP`
- 中文标题：`传输设置`
- 右上角圆形步骤标识：`01`

#### 本地地址

本地地址由文字输入框和文件夹图标按钮组成一个横向输入行。

- 输入框支持手动编辑绝对路径、`~` 路径和环境变量路径。
- 输入框示例：`/Users/kai/Data/Video/real_data/episode3_manual/mono-2`
- 右侧按钮宽度约 `48px`，与输入框等高。
- 按钮使用蓝色线框文件夹 SVG 图标。
- 按钮必须有 `aria-label="打开文件管理器"` 和 `title="打开文件管理器"`。
- 点击按钮打开系统文件夹选择器。
- 选择成功后，将返回的 POSIX 路径写入输入框，并立即持久化。
- 用户仍然可以直接修改输入框内容。
- 传输进行中时，文件夹按钮应禁用。
- 说明文字：`本地源路径或本地目标目录`。

#### 服务器地址

服务器地址不是自由文本输入框，而是可展开的多选下拉框。

- 下拉选项来自本机 `~/.ssh/config` 的具体 `Host` 别名。
- 每个选项是一个复选框。
- 选择多个别名后，摘要文本使用 ` / ` 拼接，例如 `11.20 / H800-1 / H800-2`。
- 下拉框内提供“刷新 config”操作，用于重新读取 SSH 配置。
- 说明文字：`选项来自本机 ~/.ssh/config，可多选。后台会为每台服务器拼接最终地址。`

#### 远程路径

- 使用普通文本输入框。
- 只填写远程路径部分，例如 `/home/keal_yue/DataSets/real_data/episode3_manual/mono-2/checked_videos`。
- 不允许在该字段重复填写服务器别名、`user@host:` 或 `ssh://`。
- 说明文字：`只填写服务器上的路径，不要重复填写服务器别名。`

#### 传输方向

使用两个纵向单选卡片：

- `本地 → 服务器`
  - 辅助说明：`将本地地址上传到服务器地址`
  - 值：`local_to_server`
- `服务器 → 本地`
  - 辅助说明：`将服务器地址下载到本地地址`
  - 值：`server_to_local`

选中卡片使用浅蓝背景和蓝色边框。

#### 操作按钮

- 主按钮：`开始传输`，蓝色背景，带右上箭头图标。
- 次要危险按钮：`停止传输`，浅红背景。
- 传输运行时禁用“开始传输”，启用“停止传输”。
- 未运行时禁用“停止传输”。

### 4.5 实时状态卡片

卡片标题区域包含：

- 英文眉题：`LIVE STATUS`
- 中文标题：`实时状态`
- 右上角状态胶囊。

状态胶囊至少包含以下状态：

- `就绪`
- `传输中`
- `正在停止`
- `完成`
- `部分失败`
- `失败`
- `后台未连接`

状态内容包含：

- 总体进度文字，例如 `68%`。
- 横向进度条。
- 当前速度，例如 `2.14MB/s`。
- 预计剩余时间，例如 `0:04:30`。
- 当前本地路径。
- 当前服务器与远程路径。

多服务器任务的总体百分比按服务器任务平均计算。当前速度和预计剩余时间显示正在处理的服务器的 `rsync` 数据。

### 4.6 下方区域

下方区域仍然是两列卡片。

左侧是“功能描述”卡片，包含四项：

- 双向传输。
- 多服务器。
- 适合大文件。
- 可续传。

右侧是“传输日志”卡片，使用深色等宽字体区域显示后端输出。日志可以清空，但清空只影响当前页面展示，不删除后台进程输出。

页面底部说明：`SSH 密钥和密码由本机 SSH 配置管理，工具不会保存密码。`

## 5. 本地文件夹选择器

### 5.1 交互要求

1. 用户点击本地地址右侧文件夹按钮。
2. 浏览器向本地后台发送 `POST /api/choose-folder`。
3. 后台打开系统文件夹选择器并等待用户选择。
4. 用户确认后，后台返回 POSIX 路径。
5. 前端把路径填入本地地址输入框。
6. 后台立即更新配置文件中的 `local` 字段。
7. 下次加载页面时通过 `/api/config` 恢复该路径。

用户取消选择时不修改现有输入框内容，也不修改配置文件。

### 5.2 平台实现

macOS 优先调用：

```text
/usr/bin/osascript
```

AppleScript 使用系统 `choose folder`，并返回 `POSIX path`。

Linux 依次尝试：

1. `zenity --file-selection --directory`
2. `kdialog --getexistingdirectory`

如果没有可用选择器，应返回用户可读的错误，而不是让前端显示未处理的异常。

### 5.3 持久化规则

配置文件位于应用目录：

```text
/Users/kai/project/data_transfer/transfer_tool_config.json
```

配置格式：

```json
{
  "local": "/Users/kai/Data/Video/real_data/episode3_manual/mono-2",
  "servers": ["11.20"],
  "remote_path": "/home/keal_yue/DataSets/real_data/episode3_manual/mono-2/checked_videos",
  "direction": "server_to_local"
}
```

文件夹选择成功后至少更新 `local` 字段。开始传输时更新全部四个字段。配置写入失败需要向前端返回明确错误。

## 6. SSH config 解析

### 6.1 输入来源

读取：

```text
~/.ssh/config
```

同时解析简单的 `Include` 指令。相对路径相对于当前配置文件所在目录解析。需要维护已访问文件集合，避免 Include 循环。

### 6.2 Host 过滤

提取所有 `Host` 指令中的别名，按配置文件出现顺序保留，并去重。

以下 token 不应展示在下拉框：

- 包含 `*` 的通配符。
- 包含 `?` 的通配符。
- 包含 `!` 的排除规则。

不要展示 `HostName`、`User`、`Port` 或配置注释中的内容。

### 6.3 最终地址拼接

前端只提交：

- `servers`，例如 `["11.20", "H800-1"]`
- `remote_path`，例如 `/data/video`

后台为每个服务器拼接：

```text
11.20:/data/video
H800-1:/data/video
```

rsync 通过 SSH 别名运行，确保用户 `~/.ssh/config` 中的用户名、主机、端口、身份文件和其他配置继续生效。

## 7. 传输实现

### 7.1 依赖

- Python 3 标准库。
- 系统 `rsync`。
- 系统 `ssh`。
- 本机浏览器。
- macOS 文件夹选择器需要系统 `osascript`。

不引入 Flask、Node、npm 或其他第三方运行时依赖。

### 7.2 rsync 参数

每台服务器执行一条命令，结构如下：

```text
rsync
  -rlt
  --no-owner
  --no-group
  --no-perms
  --whole-file
  --partial
  --info=progress2
  --human-readable
  --stats
  -e "ssh -T -o Compression=no"
  SOURCE
  DESTINATION
```

说明：

- `-rlt` 递归传输并保留链接与修改时间。
- 不保留远端所有者、用户组和权限，避免 macOS 本地权限冲突。
- `--whole-file` 适合视频和大型数据文件。
- `--partial` 保留未完成文件，便于再次传输。
- `--info=progress2` 输出总体进度、速度和预计剩余时间。
- 不启用压缩，避免对已经压缩的视频文件浪费 CPU。

命令必须通过参数数组传给 `subprocess.Popen`，不要把用户输入拼进 shell 命令字符串。

### 7.3 本地路径规则

本地路径需要执行：

1. 去除首尾空白。
2. 展开环境变量。
3. 展开 `~`。
4. 转换为绝对路径。

上传时本地源路径必须存在。下载时本地目标目录不存在则自动创建。

### 7.4 多服务器执行策略

- 同一任务内的服务器按选择顺序串行执行。
- 当前服务器完成后再开始下一台。
- 任何服务器失败都要记录该服务器的返回码，并继续处理后续服务器。
- 所有服务器完成后：
  - 全部成功，状态为 `完成`。
  - 部分失败，状态为 `部分失败`。
  - 全部失败，状态为 `失败`。
- 用户点击停止后，向当前 rsync 进程组发送 `SIGINT`。任务状态为 `已停止`，再次开始时依靠 `--partial` 续传。

## 8. 后端服务与 API

### 8.1 服务生命周期

- 使用 Python 标准库 `ThreadingHTTPServer`。
- 只绑定 `127.0.0.1`，不对局域网开放。
- 默认端口 `8765`。
- 如果端口被占用，依次尝试后续最多七个端口。
- 启动时输出最终 URL。
- 直接运行 Python 文件时可以自动打开浏览器。
- 双击启动脚本时使用 `nohup` 将服务独立运行，并等待健康检查成功后打开浏览器。
- 启动脚本检查 `/api/health` 的版本号，避免复用旧服务。

### 8.2 GET API

#### `GET /api/status`

返回当前任务状态：

```json
{
  "running": false,
  "status": "就绪",
  "percent": 0,
  "speed": "0 B/s",
  "eta": "--",
  "direction": "local_to_server",
  "local": "",
  "servers": [],
  "remote_path": "",
  "current_server": "",
  "return_code": null,
  "results": [],
  "logs": []
}
```

#### `GET /api/hosts`

返回：

```json
{"hosts": ["11.20", "H800-1", "H800-2"]}
```

#### `GET /api/config`

返回上次保存的本地地址、服务器、远程路径和方向。

#### `GET /api/health`

返回：

```json
{"ok": true, "version": "3"}
```

### 8.3 POST API

#### `POST /api/start`

请求体：

```json
{
  "local": "/Users/kai/Data/Video/real_data/episode3_manual/mono-2",
  "servers": ["11.20", "H800-1"],
  "remote_path": "/data/video",
  "direction": "local_to_server"
}
```

校验：

- 至少选择一台服务器。
- 远程路径不能为空。
- 远程路径不能重复包含服务器地址。
- 上传源路径必须存在。
- 同一时间只能有一个任务运行。

#### `POST /api/stop`

停止当前任务。没有运行任务时返回成功且不改变状态。

#### `POST /api/choose-folder`

打开本机系统文件夹选择器。

成功返回：

```json
{
  "ok": true,
  "path": "/Users/kai/Data/Video/real_data/episode3_manual",
  "cancelled": false
}
```

用户取消返回：

```json
{
  "ok": true,
  "path": null,
  "cancelled": true
}
```

错误返回 HTTP `400` 和：

```json
{"ok": false, "error": "错误描述"}
```

## 9. 前端状态刷新

- 页面加载后请求 `/api/hosts` 和 `/api/config`。
- 页面每 `500ms` 请求一次 `/api/status`。
- 进度条、速度、ETA、状态和日志根据返回结果更新。
- 后端连接失败时显示 `后台未连接`，只提示一次，避免每次轮询都弹窗。
- 传输日志使用完整日志数组渲染，并自动滚动到底部。
- 点击“清空”只清空当前浏览器中的日志展示。

## 10. 错误处理

以下错误必须显示中文可读信息：

- 找不到 `rsync`。
- 找不到 `ssh`。
- 找不到系统文件夹选择器。
- 本地源路径不存在。
- 服务器为空。
- 远程路径为空。
- 远程路径错误地包含服务器地址。
- 传输正在进行时重复启动。
- 选择器取消。
- 配置文件读写失败。
- 后端服务断开。

浏览器页面不应直接暴露 Python traceback。详细 rsync 输出写入“传输日志”。

### 文件职责

- `transfer_tool.py`：HTTP 服务、SSH config 解析、文件夹选择器、配置持久化、rsync 进程和状态管理。
- `web/index.html`：页面结构和中文文案。
- `web/style.css`：布局、颜色、卡片、按钮、响应式样式。

## 12. 安全与可靠性要求

- 后端只监听 `127.0.0.1`。
- 不保存 SSH 密码。
- 使用 SSH 配置和密钥完成认证。
- 用户路径通过参数数组传给子进程，避免 shell 注入。
- 服务器别名必须来自 SSH config 选择结果。
- 选择器和传输状态访问都在本地后台完成，不把本地绝对路径上传到第三方服务。
- 传输停止后必须保留部分文件，便于重新开始。
- 多服务器下载必须隔离目标目录，避免同名文件覆盖。
